Quick start

  1. Download the example ZIP and drop it into Fullscreen → Manage widgets. Enable it and save order/enabled state.
  2. Change the message and theme in Widget settings, then choose Show on device. Tap the card on a device or virtual fullscreen to increment the counter.
  3. Extract the ZIP and edit main.js. Choose a unique id for a new widget; increase version when updating the same widget. ZIP the files inside the folder, not the enclosing folder, and import again.
Widgets run in Studio on your PC. No widget code is installed on ESP32 or Android. Passive previews do not change the counter; its memory-only state resets when Studio restarts.

Responsive layout

Existing widgets keep 480×320. New JavaScript widgets requiring viewport:1 can arrange content using api.width, api.height and api.contentRect, with touch in the same coordinates.

Requires Windows Studio 0.9.41 or macOS 0.9.40 build148 or later with viewport:1. Available on Mac/Windows virtual screens. ESP32 and current Android connections retain the 480×320 fallback. This does not increase raster transmission resolution.

Begin with a small render function like this. The installable example also includes touch deduplication, settings and translations.

const widget = {
  render(api) {
    api.useThemeBackground?.();
    const c = api.canvas;
    c.fillStyle = '#86E9C6';
    c.font = '24px sans-serif';
    c.textAlign = 'center';
    c.fillText(api.settings.message, 240, 160);
  }
};

APIs & runtime

Drawing & touch

Legacy 480×320 or opt-in responsive coordinates, up to 700 drawing commands and 32KiB state. For taps use packageVersion 3, api.inputs, api.active and sequence deduplication. Studio owns Back and side navigation.

Settings & images

Declare text, toggles and choices in settings.json. Use theme backgrounds, translations, bounded JPEG backgrounds and static WebP sprites.

Network & safety

Declare only required HTTPS hosts and use api.httpJson cached results. Studio’s internet switch applies. File modification, arbitrary commands, camera and microphone APIs are not exposed.

Shared host services

Read-only system/media/weather snapshots and declarative feed/photo services require explicit contracts and permissions. They are not arbitrary JavaScript functions.

Read the API guide

JavaScript runs in synchronous render(api). npm, DOM and direct fetch are unsupported. Actual frame rate depends on the host, display and transport.

Test & share

  • Check defaults, long text, languages and light/dark themes.
  • Check passive preview, active fullscreen, repeated taps and widget switching.
  • For online widgets test loading, service errors and internet disabled. Never put secret keys in a ZIP.
  • Update the same ID with a higher version and verify saved options survive. Removing a widget deletes its managed settings.
  • When sharing, include the minimum Studio version, license, attribution and what you tested on each platform.
