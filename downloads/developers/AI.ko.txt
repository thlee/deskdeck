첨부한 Baroham 위젯 API 안내서(API.ko.md)와 Hello 예제를 기준으로 아래 위젯을 만들어 주세요.
만들 기능: [여기에 기능을 적으세요]
대상: Windows Studio 0.9.41 이상 / macOS 0.9.40 build148 이상.

1. 기본적으로 외장 JavaScript ZIP으로 만들고, 터치가 필요하면 packageVersion 3을 사용하세요.
2. manifest.json, main.js, settings.json을 ZIP 루트에 넣고, 고유 ID와 major.minor.patch 버전을 지정하세요.
3. 문서에 없는 API, npm, DOM, fetch, 파일 접근, OS 실행, 카메라·마이크 기능을 만들거나 가정하지 마세요. 미지원 요구는 먼저 설명하세요.
4. 기본은 기존 480×320 좌표입니다. 반응형 요청은 Windows 0.9.41 / macOS 0.9.40 build148 이상에서 requires에 canvas/settings/touch/viewport를 선언하고 api.width·height·contentRect로 매 프레임 배치하세요. 터치는 이미 같은 좌표이며 소수일 수 있습니다. 기존 기기 연결은 480×320으로 되돌아갑니다. 상단 뒤로·좌우 이동 영역은 Studio가 관리합니다.
5. render(api)는 동기식, 700개 이하 그리기 명령, 상태는 32KiB 이하로 유지하세요.
6. api.active가 false인 미리보기에서 게임 상태를 변경하지 말고, 터치 sequence를 중복 처리하지 마세요.
7. 테마는 api.useThemeBackground?.()로 요청하고, 설정·한국어/영어/일본어/중국어 번역·긴 문구를 처리하세요.
8. 인터넷이 필요할 때만 정확한 HTTPS 호스트를 선언하고 api.httpJson 캐시 결과를 사용하세요. 로딩/실패/인터넷 차단을 고려하고 비밀키를 넣지 마세요.
9. state는 영구 저장이 아닙니다. 사용자 옵션은 settings.json으로 제공하세요. 기존 ID 업데이트는 버전을 높이고 설정 호환성을 유지하세요.
10. 결과로 파일 트리, 모든 파일 내용, 루트 구조가 올바른 ZIP, 사용법, 라이선스·출처, 최소 버전 및 검증 체크리스트를 제공하세요.
11. 실제 Studio에서 실행하지 않았다면 테스트 완료라고 쓰지 마세요. Windows·Mac·기기별 미검증 항목을 구분하세요.

Windows 0.9.41 / macOS 0.9.40 build148 이상은 일반 JSON 상태만 허용합니다(직렬화된 UTF-8 32KiB 이하, 깊이20·값 노드4096 이하). 버퍼·형식화 배열·Map/Set·Date·순환 참조·무한대/NaN을 저장하지 마세요. 선언된 HTTPS 호스트는 공개 IP로만 해석되어야 하며 내부 주소를 차단하고 수신 중 응답 용량을 제한합니다. 강화된 검사는 위의 지원 버전부터 적용됩니다.

Windows 0.9.41 / macOS 0.9.40 build148 이상은 실행 오류나 안전 규칙 위반이 발생한 위젯을 즉시 사용 중지합니다. 사유·시각을 저장하고 대기 중인 작업을 취소하며 미리보기를 포함한 재실행을 막습니다. Studio 재시작·ZIP 업데이트·재설치로 자동 해제되지 않습니다. 위젯 관리에서 사유를 확인하고 사용자가 명시적으로 다시 켜야 실행됩니다. 중지된 ID의 ZIP을 다시 설치하면 파일만 교체하며 설치 미리보기 실행과 중지 해제를 하지 않습니다. 다시 위반하면 재차 중지합니다. 오프라인·DNS 조회 실패·일반 통신 시간 초과·서버 오류·잘못된 JSON 응답은 사용 중지 사유가 아닙니다. 내부 IP·미선언 URL·응답 용량 초과는 중지 사유입니다. 중지 기록 저장에 실패하면 오류를 알리고 현재 실행 중에는 메모리의 차단 상태를 유지합니다.

장면별 설정과 패키지 소리 (Studio 0.9.45+)
설정 항목에 `visibleWhen`을 사용하려면 `settings:2`를 선언합니다. 다른 choice/toggle 항목의 키와 정확한 유효 값을 1–3개 지정하며 모두 일치할 때만 표시합니다. 숨긴 값도 보존·저장되고 취소하면 편집을 버립니다. 표현식은 실행하지 않습니다.

`api.playSound("rain", 0.2)`에는 `audio:1`, `permissions.audio:true`, `sounds` 선언이 필요합니다. 각 소리는 패키지 내부 `assets/<name>.wav`로 연결합니다. 44바이트 표준 헤더 PCM16 WAV, 모노/스테레오, 8–48 kHz, 1–30초만 허용합니다. 최대 8개, 파일당 1 MiB, 합계 2 MiB입니다. PC 스피커에서 소리 하나를 반복 재생하며 활성 프레임마다 요청을 유지합니다. 요청을 생략하거나 음량 0으로 중단합니다. 음량은 0–1의 유한수입니다. 미리보기·설치 검사에서는 재생하지 않습니다. 위젯 종료·화면 절전·격리·앱 종료 시 멈춥니다. 호스트가 재생기를 관리하며 마이크·임의 URL/경로·파일 쓰기 권한은 없습니다. Android/ESP32에는 이 소리를 전송하지 않습니다.

상호작용하는 휴식 위젯은 manifest의 `autoRotate:true`로 Studio의 일반 위젯 순환을 허용할 수 있습니다. 게임 호환성을 위해 기본값은 false입니다. Relax 패키지는 장면별 설정과 자체 제작 빗소리의 완전한 예제입니다.

`audio:2`(Studio 0.9.45+, Android 0.5.56+)는 같은 API와 제한을 사용하되 연결된 Android 기기에서 재생합니다. 가상 화면만 사용하는 경우 PC에서 재생합니다. ESP32 및 audio_cache 기능이 없는 Android에는 소리를 보내지 않으며 PC로 우회하지 않습니다. Android는 `audio_cache:"pcm16-v1"`을 광고하고 SHA-256으로 검증한 WAV를 앱 내부 캐시에 보관합니다. USB와 Wi-Fi 모두 audio_select → 캐시 없을 때 audio_begin/audio_chunk/audio_finish를 사용하며 청크는 65,536바이트 이하입니다. 전체 캐시는 8개·8 MiB로 제한합니다. widget_layout의 audio_hash/audio_volume은 다음 정상 프레임과 함께 적용합니다. 음량만 변경해도 재생기는 유지하고, 장면에서 소리 요청을 빼면 중단합니다. 앱이 배경으로 가거나 연결·화면·위젯이 종료되면 중단합니다. 오디오 포커스를 잃으면 해당 소리를 자동으로 반복 재시작하지 않습니다. 기존 `audio:1`은 PC 재생을 유지합니다. 파일 수정·삭제 권한은 위젯에 제공하지 않으며, 호스트의 전용 캐시 정리만 허용합니다.
